## 1. Фундаментальная модель авторизации: WSRPC vs REST

В традиционном REST API каждый HTTP-запрос независим и передает заголовок `Authorization: Bearer <JWT>`. Бэкенд на каждый запрос распаковывает и валидирует криптографическую подпись.

В **`PyFerro`** концепция принципиально иная:
1. **Постоянное соединение (Stateful Socket):** Клиент открывает постоянное дуплексное WebSocket-соединение.
2. **Аутентификация соединения один раз (O(1)):** После успешного входа объект сессии сокета помечается авторизованным (`session.data = AuthSession(...)`).
3. **Мгновенная проверка прав:** Все последующие RPC-вызовы в рамках этого соединения проверяются в оперативной памяти за **доли микросекунды**, без повторных обращений к БД и без проверки крипто-подписей JWT на каждый клик.
4. **Двойной контур:**
   - **WebSocket-контур:** Управляет RPC-методами, реактивными событиями и стримингом данных.
   - **HTTP-контур:** Управляет раздачей статики, загрузкой файлов (2PC `/upload`) и доступом к панели `/crud`. Для HTTP-контура используются Cookie (`ferro_session`, `ferro_crud_session`).
5. **Бесшовный авто-логин (`auto_auth_ws=True`):** При обрыве сети и переподключении сокета сервер автоматически считывает Cookie браузера во время WebSocket Handshake и восстанавливает сессию сокета в памяти **до** выполнения бизнес-запросов.

## 2. Хранение и хэширование паролей: почему «пароль не совпадает»

Самая частая проблема при миграции старых проектов или создании новых — **несовпадение формата хэша пароля**.

### 2.1. Канонический алгоритм PBKDF2-SHA256

Канонический стандарт `PyFerro` использует **PBKDF2 с HMAC-SHA256** и обязательным хранением соли и ключа в кодировке **Base64**.

Строка `password_hash` в БД обязана иметь следующий формат:
```text
pbkdf2_sha256$<iterations>$<salt_b64>$<key_b64>
```

Где:
- `pbkdf2_sha256` — идентификатор алгоритма (префикс).
- `iterations` — число итераций (по умолчанию `100000`).
- `salt_b64` — 16 случайных байт соли в формате Base64.
- `key_b64` — 32 байта производного ключа (хэша) в формате Base64.
- Разделитель частей — строго знак доллара `$` (НЕ двоеточие `:`!).

### 2.2. Анти-паттерны и рудименты старых проектов

| Ошибочный формат в БД | Почему не работает | Как исправить |
|---|---|---|
| `pbkdf2:sha256:10000$salt$hash` | Двоеточия вместо знака `$` (рудимент старого Werkzeug/Flask) | Использовать канонический хэшер `pyferro.core.security.hash_password` |
| `salt$hash` (hex строка) | Соль или хэш записаны в шестнадцатеричном виде вместо Base64 | Перехэшировать пароль через утилиту командной строки |
| Сырой пароль или SHA256 без соли | Нарушение безопасности и несовпадение сигнатуры алгоритма | Сбросить пароль администратора через CLI |

### 2.3. Утилита смены/сброса пароля (CLI)

Для безопасного обновления пароля пользователя в базе данных без запуска сервера используйте встроенную утилиту:

```bash
python server.py --set-admin-password "МойНовыйПароль" --login admin
```

Или в коде приложения:
```python
from pyferro.core.security import hash_password

new_hash = hash_password("новый_пароль")
user.password_hash = new_hash
await db_session.commit()
```

## 3. Бэкенд: Контракты RPC-методов и сессии

### 3.1. Правило префикса `login.` и флага `public=True` (Default Deny)

По умолчанию в PyFerro действует политика **Default Deny**: все методы требуют авторизации, кроме:
1. Методов, имя которых начинается с `login.` (например, `login.submit`, `login.get_key`, `login.refresh`, `login.whoami`).
2. Методов с явным флагом `@app.rpc("auth.login", public=True)`.

### 3.2. Использование встроенного плагина `plugins.auth`

Плагин `pyferro.plugins.auth` регистрирует полный комплект готовых методов:
* `login.submit` — стандартная аутентификация по логину и паролю.
* `login.get_key` — генерация эфемерного публичного ключа RSA для безопасного шифрования пароля на клиенте.
* `login.secure` — прием зашифрованного RSA-пароля, расшифровка приватным ключом сервера и аутентификация.
* `login.whoami` — проверка текущего пользователя и его прав.
* `login.refresh` — продление сессии по `refresh_token`.
* `auth.logout` — отзыв сессии и удаление токена.

### 3.3. Автоматическая авторизация WebSocket по Cookie (`auto_auth_ws`)

В `FerroApp` по умолчанию включен флаг `auto_auth_ws=True`. При подключении сокета сервер считывает Cookie `ferro_session` / `ferro_crud_session` во время WebSocket Upgrade и авторизует сокет **до выполнения первого запроса**.

### 3.4. Системные операции и обход RLS (`system_db_session`, `system_bypass`)

Если в системных RPC-хендлерах, фоновых воркерах или сервисных задачах требуется работать с моделями пользователей или защищенными таблицами в обход Row-Level Security (RLS), используйте канонические контекстные менеджеры:

```python
from pyferro import system_db_session, system_bypass
from sqlalchemy import select

# 1. Автономная асинхронная сессия в обход RLS:
async with system_db_session() as db:
    user = (await db.execute(select(User).where(User.login == username))).scalar_one_or_none()

# 2. Временное отключение RLS внутри уже открытой сессии:
with system_bypass():
    user = await User.get_permissions_by_id(db, user_id)
```

## 4. Фронтенд: Интеграция с клиентом `wsrpc.ts`

Вся клиентская логика аутентификации, безопасного RSA-входа, обновления токенов, установки Cookies и шлюза от гонок запросов (Session Gatekeeper) **уже встроена из коробки** в официальный клиент [`client/wsrpc.ts`](../client/wsrpc.ts) (подсистема `rpc.auth` и экспортируемый синглтон `auth`).

> 📖 **Исчерпывающее руководство по всем возможностям клиента:**  
> Смотрите [docs_ru/client_guide.md](client_guide.md) (быстрый старт, реактивность, стриминг, события и генерация типов).

### Быстрый пример авторизации на фронтенде:
```typescript
import { rpc, auth } from './wsrpc';

// 1. Стандартный вход по логину/паролю
await auth.login({ username: 'alex', password: 'secret' });

// 2. Или безопасный вход с автоматическим RSA-OAEP шифрованием на клиенте
await auth.loginSecure({ username: 'alex', password: 'secret' });

// 3. Доступ к состоянию
console.log(auth.user);     // AuthUser | null
console.log(auth.isValid);  // boolean

// 4. Реактивная подписка на смену пользователя (Svelte $auth, React, Vue)
auth.onChange((user) => {
    console.log('Пользователь обновился:', user?.username);
});

// 5. Выход из аккаунта (очищает сокет, Cookies и localStorage)
await auth.logout();
```

## 5. Интеграция с Панелью Управления CRUD (Zero-Leakage 404)

Если администратор пытается открыть `http://localhost:8080/crud` и видит **`404 Not Found`**, это механизм **Zero-Leakage (404)**:  
Эндпоинт `/crud` намеренно маскируется под несуществующую страницу, если запрос не содержит валидного Cookie сессии администратора (`ferro_crud_session` или `ferro_session`).

### Как гарантировать работу перехода в `/crud`:
1. **На бэкенде** при авторизации администратора зарегистрируйте его сессию:
   ```python
   if role == "admin":
       from pyferro.plugins.crud import create_crud_session
       create_crud_session({"username": user.login, "role": "admin"}, token=token)
   ```
2. **На фронтенде** клиент `wsrpc.ts` устанавливает необходимые куки автоматически при вызове `auth.login()`.
3. После этого открытие `window.open('/crud', '_blank')` сразу открывает панель управления.

## 6. Таблица типичных ошибок и решений (Troubleshooting)

| Симптом | Причина | Решение |
|---|---|---|
| **`Неверный логин или пароль` при верных данных** | Не совпадает алгоритм/формат хэша в БД (вместо `pbkdf2_sha256$<iter>$<salt_b64>$<key_b64>` лежит hex или sha256) | Сбросить пароль через CLI: `python server.py --set-admin-password "пароль" --login "логин"` |
| **`Permission Denied` (-32000) при вызове метода логина** | Метод назван не с префикса `login.` (например `auth.login`) и не имеет флага `public=True` | Добавить `@rpc_method("auth.login", public=True)` или переименовать в `login.submit` |
| **При обновлении страницы пользователь разлогинивается** | Фронтенд не сохраняет `refresh_token` в `localStorage` или не устанавливает `ferro_session` Cookie | Использовать встроенный `auth.login()`, который делает это автоматически |
| **При переподключении сокета бизнес-запросы падают с ошибкой прав** | Запросы улетают до восстановления сессии сокета | Клиент `wsrpc.ts` автоматически защищает запросы через встроенный Gatekeeper |
